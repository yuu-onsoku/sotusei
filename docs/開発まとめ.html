1. 全体像

「ねこの相談室」に、質問と回答を中心とした機能を追加し、本番環境（Render）で正しく動くように整えました。大きく分けると次の3種類の作業です。

機能追加 回答の閲覧・いいね・検索・編集・削除・画像アップロード
バグ修正 いいねが正しく動かない問題
インフラ 本番の500エラー・デプロイ失敗・画像の保存先・日本語化

2. 質問の詳細ページ（回答の閲覧）機能追加

質問をクリックすると、質問の本文と、そこに寄せられた回答の一覧を見られるページを作りました。

やったこと

  • ルーティングに show を追加（/questions/:id）
  • コントローラで質問とその回答を読み込み、投稿順に表示
  • 一覧のカードのタイトルや回答数から、詳細ページへ移動できるようにリンクを設定
  • 回答投稿後は、一覧ではなく詳細ページに戻るように変更（自分の回答がすぐ見える）

主なファイル: app/views/questions/show.html.erb, app/controllers/questions_controller.rb

N+1問題への対応: 回答一覧を表示するとき、回答ごとに投稿者を1回ずつDBに問い合わせると遅くなります（これを「N+1問題」と呼びます）。includes を使ってまとめて読み込むことで、問い合わせ回数を減らしています。

3. 画像アップロード機能追加

回答にも画像を添付できるようにし、質問と回答で共通の画像処理をまとめました。

  • ImageAttachable という共通モジュール（concern）を作り、「画像は任意・形式はPNG/JPEG/GIF/WEBP・5MBまで」という検証を1か所に集約
  • 質問モデルと回答モデルの両方がこれを取り込むだけで、同じ画像機能を持てるように
  • 回答フォームのダミー入力を、実際に保存される入力へ置き換え

主なファイル: app/models/concerns/image_attachable.rb

concern（コンサーン）とは: 複数のモデルで使い回したい共通の処理をまとめておく仕組みです。同じコードを何度も書かずに済み、修正も1か所で済みます。

4. いいね機能（肉球ボタン）機能追加

肉球ボタンを押すと「いいね」できる機能です。段階的に育てました。

段階内容
①質問にいいねを付ける。1人が同じ質問に付けられるのは1回まで（DBの制約とモデルの検証の二重で保証）
②Xのように、押した瞬間に反応してページが再読み込みされない操作感に
③回答にもいいねできるように拡張。質問用と回答用でコードを重複させないため、polymorphic 関連という仕組みで1つのテーブル・部品を共用
polymorphic（ポリモーフィック）関連とは: 1つの「いいね」テーブルが、質問にも回答にも紐づけられる仕組みです。likeable_type（対象の種類：質問か回答か）と likeable_id（対象のID）の2つを持つことで、どちらにも対応できます。

主なファイル: app/models/like.rb, app/models/concerns/likeable.rb, app/controllers/likes_controller.rb, app/views/likes/

途中で「詳細ページのいいねは不要」というご要望があり、詳細ページの質問へのいいねは外し、一覧と回答にだけ残しています。

5. いいね機能のバグ修正バグ修正

「押しても1回目が効かない」「再読み込みで消える」という不具合が起きていました。原因は複数あり、順に突き止めて直しました。

原因1：画面とサーバーの状態がズレていた

最初の作りは「押した瞬間に見た目だけJavaScriptで変え、サーバーは結果を返さない」方式でした。ボタンには「次はいいねか、取り消しか」の情報が埋め込まれていたため、ブラウザの「戻る」操作などで画面が古くなると、次のクリックが逆の操作として送られてしまいました。

原因2：同じ操作が二重に届くと打ち消し合っていた

「押すたびに反転（トグル）」方式にした時期があり、1回のクリックで送信が2回飛ぶと「付ける→外す」で元に戻ってしまいました。実際のサーバーログにも、その現象が記録されていました。

原因3：連打防止のロックが解除されなくなっていた

二重送信を防ぐガードを入れたところ、解除のタイミングを逃してボタンが完全に無反応になってしまいました。

最終的な直し方

  • 「いいねする」と「取り消す」を別々の操作に分離。同じ操作が何回届いても結果が変わらないようにした（付けるは1件のまま、外すは0件のまま）
  • 押したあとはサーバーがボタンを描き直し、表示を必ずサーバーの状態に合わせる（ズレても自動で直る）
  • 「戻る」で古い状態が復元されないよう、キャッシュを無効化
  • 問題のあった連打ガードは削除
いちばん大事だった気づき: 実は「動かない」の一番の原因は、テストしていたのが本番サイト（Render）で、そこに修正が反映されていなかったことでした。手元（ローカル）では直っていたのに、本番には古いコードが動き続けていたのです。ここから、次のデプロイ問題の調査につながりました。

6. 質問の検索機能機能追加

一覧ページの検索バーで、実際に質問を絞り込めるようにしました。

  • 検索バーがタイトル欄と同じ幅になるようデザインを調整（Tailwindの設定値の都合で幅が潰れていたのを修正）
  • タイトルまたは本文にキーワードを含む質問を、大文字小文字を区別せず部分一致で検索
  • 記号（% など）を入れても誤作動しないよう、安全にエスケープ
  • 検索結果が0件のときの案内メッセージと、条件クリアのボタンを追加

主なファイル: app/models/question.rb（search メソッド）, app/views/questions/index.html.erb

7. 編集・削除機能機能追加

質問と回答を、投稿した本人が編集・削除できるようにしました。

  • 投稿フォームをそのまま編集フォームとして使い回し、新規なら「投稿」、編集なら「更新」に自動で切り替え
  • 編集・削除のリンクは投稿者本人にだけ表示
  • 他人が直接URLを叩いても編集・削除できないよう、サーバー側でも本人確認（見た目を隠すだけでなく、処理側でもブロック）
  • 削除は取り消せないため、確認ダイアログを必須に
  • 質問を削除すると、ぶら下がる回答・いいね・画像も一緒に片付く

主なファイル: app/controllers/questions_controller.rb, app/controllers/answers_controller.rb

セキュリティのポイント: ボタンを隠すだけでは、URLを直接入力されると防げません。「一覧を自分の投稿だけに絞ってから探す」という書き方にすることで、他人の投稿はそもそも見つからず、編集・削除できないようにしています。

8. 日本語化・日本時間インフラ

投稿時刻を日本時間に

本番サーバーの時刻がUTC（協定世界時）だったため、14時24分の投稿が「05:24」と表示されていました。設定を「東京」にして、日本時間で表示されるようにしました。

エラーメッセージを日本語に

ログイン失敗時の「Invalid Email or password.」などが英語だったので、日本語化しました。

変更前変更後
Invalid Email or password.メールアドレスまたはパスワードが違います。
Password is too shortパスワードは8文字以上で入力してください
Username can't be blankユーザー名を入力してください
  • rails-i18n（Rails本体のメッセージ）と devise-i18n（ログイン系のメッセージ）を導入
  • 項目名の訳（Title→タイトル など）を config/locales/ja.yml に用意

主なファイル: config/application.rb, config/locales/ja.yml

9. 本番デプロイのトラブル解決インフラ

本番サイトで発生していた複数の問題を、順に切り分けて解決しました。ここが今回いちばん時間をかけた部分です。

① 全ページが500エラー → 本番DBが空だった

ヘルスチェック（/up）は正常なのに、他のページが全部エラー。調べると、本番のデータベース（Neon）にテーブルが1つも作られていませんでした。マイグレーション（テーブルを作る作業）を実行して解決しました。

② 画像がデプロイのたびに消える → Cloudinaryへ

画像をサーバー内のディスクに保存していたため、再起動やデプロイのたびに消えていました。外部の画像保管サービス Cloudinary に保存先を変更しました。

Renderの無料プランは、一定時間アクセスがないと停止し、再起動でファイルが消えます。だから画像は外部に置く必要があります。

③ デプロイが失敗する → 3つの設定ミス

デプロイのログを1行ずつ読み解き、原因を特定しました。

症状原因対処
起動時にエラーで停止 CLOUDINARY_URL の値が cloudinary:// で始まっていなかった（別のURLが入っていた） 正しい接続文字列に修正
環境が deployment になる RAILS_ENV が未設定で、本番モードで起動していなかった 環境変数に RAILS_ENV=production を追加
失敗しても気づけない／DBが空のまま ビルド手順が ; でつながれ、途中の失敗が無視されていた。マイグレーションも含まれていなかった ビルド用スクリプト bin/render-build.sh を作成

作成したビルドスクリプトの中身（要点）:

set -o errexit          # 途中で失敗したら止める
bundle install          # ライブラリの用意
yarn install            # JS/CSSのライブラリ
rails assets:precompile # JS/CSSのビルド
rails db:migrate        # テーブルの作成・更新

④ 無料プランのスリープ対策

無料プランは15分アクセスがないと眠り、次のアクセスで復帰に約1分かかります。10分おきにヘルスチェックを叩いて起こし続ける仕組み（GitHub Actions）を追加しました。

主なファイル: bin/render-build.sh, .github/workflows/keep-alive.yml, config/storage.yml
